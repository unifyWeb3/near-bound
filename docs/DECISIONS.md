# Decisions

One line per decision, with the reason and the date.

| Decision | Reason | Date |
| --- | --- | --- |
| The policy lives in the `bound-policy` crate as a pure function | The same rules are implemented in the paper harness in JavaScript, and both are tested against the same cases. A pure function can be tested without a chain. | 2026-11-05 |
| The contract writes a receipt for every decision, denials included | A reader should be able to find the refusals without guessing an id. `get_receipt_count` was added so the ids can be walked. | 2026-11-05 |
| The block timestamp is converted to seconds before the policy engine sees it | The engine compares seconds. A nanosecond value made every period look finished, which reset the budget on every call. | 2026-11-05 |
| The receipt is written when the transfer settles, not when the owner approves | The transfer can fail. A receipt written at approval would say the money moved when it did not. Writing it in the callback means a receipt never lies, and no receipt is ever rewritten. | 2026-11-10 |
| The approval reserves the budget and the failed settlement gives it back | Two approvals in the same period must not go over the budget together, and a payment that never happened must not eat into the period. | 2026-11-10 |
| The receipt ledger and the policy layout are frozen | The contract is live and its state is already stored. New enum variants are appended, never inserted, so the stored values keep their borsh discriminants. | 2026-11-10 |
| `register_agent` refuses an agent that already has a policy | Registering wrote a fresh policy over the old one, which wiped the spend, the nonce and the request count of a live agent. The limits change through `set_budget`, `set_max_single_spend` and `set_rate_limit`, which keep the counters. | 2026-11-10 |
| The live policy is 5 NEAR an hour and 1 NEAR a payment | The old figures were 0.00000005 NEAR against a treasury of 19.99 NEAR, so the two numbers on the page contradicted each other. | 2026-11-11 |
| The amounts go into the CLI as base64 encoded JSON | The CLI reads `json-args` into a JSON value, and a number bigger than 2^53 comes back as a float. `base64-args` carries the exact bytes. | 2026-11-11 |
| The contract is redeployed without an init call | An init call replaces the state. A deploy with no init call keeps every receipt, request and policy. | 2026-11-11 |
| The public product is renamed Certalyn; the repository, crates, NEAR accounts, and historical hashes keep their technical identifiers | SpendGuard is a crowded product name; Certalyn is distinct. The rename applies to product copy only, not to `near-bound`, `bound-contract`/`bound-policy`, the `bound-*` accounts, or historical evidence. | 2026-11-13 |
| The README separates the historical deployed artifact from the local remediation branch | The remediation Wasm is not deployed, no redeployment is authorized, and the remediation artifact will not match the live historical hash. No redeployment is presented as live. | 2026-11-13 |
| The Rust toolchain is pinned to 1.99.1 with wasm32-unknown-unknown, rustfmt, and clippy | A single pinned toolchain keeps builds reproducible and CI identical across machines. | 2026-11-13 |
| Binaryen 133 is pinned by version and SHA-256 in scripts/build-wasm.sh | The optimizer version and its checksum are fixed together so the wasm bytes do not drift. | 2026-11-13 |
| A deterministic Wasm build script builds twice and compares SHA-256 bytes, writing a machine-readable manifest | The remediation artifact must be reproducible; it is never compared to the historical live hash. | 2026-11-13 |
| scripts/claims.py --check ignores rolling policy fields while checking invariants and keeps historical receipt hashes checked | period_start, spent, remaining, rate_count, last_nonce, request_count legitimately move; budget, max_single_spend, rate_limit, period_seconds, vendors, revoked must not drift. | 2026-11-13 |
| CI runs shellcheck, a read-only dependency vulnerability check, fake-NEAR shell tests, and the claims check with rolling fields ignored | These gates run without network, keys, or spending, and fail only on known vulnerabilities or invariant drift. | 2026-11-13 |
| demo/agent.sh and demo/protocol_arm.sh build JSON via python json.dumps + base64, validate amounts and account IDs, use a monotonic nonce counter with atomic locking, and poll for settlement | The old scripts built JSON with shell interpolation, used date +%s nonces, and slept fixed intervals; all three are unreliable against a live chain. | 2026-11-13 |
| The audit of 2026-11-14 found two broken flows and one defect that could strand money, and all three are fixed before anything else | A flagged request could never be approved, the console sent arguments the contract could not read, and the settlement callback could run out of gas and leave a reservation with no way out. Each fix has a test. | 2026-11-14 |
| `approve_request` accepts an open request, and a flagged request needs the owner | The owner path used to delegate to a method that only accepted `Pending`, so a flagged request could never be decided. The runner still cannot approve a flagged request. | 2026-11-14 |
| The settlement accounting lives in sidecars keyed by agent and period, and the callback never walks the request history | The old callback read every request of the agent to work out the reservations, so the gas cost grew with the ledger and a callback that ran out of gas left the budget reserved for good. | 2026-11-14 |
| The owner can reconcile a request whose callback never arrived | The transfer receipt tells the owner whether the money moved. `reconcile_request` settles the reservation either way and writes the receipt. | 2026-11-14 |
| A failed payment gives the rate slot back | The payment never happened, so it should not use one of the payments the owner allowed per minute. | 2026-11-14 |
| The accepted nonce is tracked per agent, next to the approved nonce | A nonce that was accepted and never decided could be used again while the first request was still open. | 2026-11-14 |
| A receipt that has no request behind it carries the sentinel `u64::MAX` | Request id zero is a real request, so it cannot double as the marker for a receipt written before any request existed. | 2026-11-14 |
| The console writes JSON argument objects, never positional Borsh | near-sdk reads the arguments of a mutating method as JSON. The old client encoded Borsh, so no browser write could succeed against the contract. | 2026-11-14 |
| The console reads one agent's receipts through a paged view and falls back to the historical scan | Reading the whole ledger of every contract to show one agent does not scale, and the historical deployment has no paged view yet. | 2026-11-14 |
| The receipt cache drops the receipts the chain cannot have any more | A deployment that was wiped starts its receipt ids at zero again, and a cached receipt from a state that is gone must not be shown as current. | 2026-11-14 |
| The build script remaps the target directory as well as the source paths | Two builds in two directories were two different artifacts, because the path of the build directory reached the bytes. The double build now compares equal. | 2026-11-14 |
| The expected Wasm hash is committed in docs/wasm-lock.json and CI fails when the build differs | The claim that the deployed code is this source has to be falsifiable, not a promise in a README. | 2026-11-14 |
| The console keeps the cream and jade palette, with a serif for statements, a sans for reading and a mono for machine output | The console is a record, not an app. A printed reading surface with one accent reads as evidence. The typefaces are self-hosted, so the page works with no third party request. | 2026-11-14 |
